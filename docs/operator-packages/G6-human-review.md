# 編集レビュー・訂正/撤回演習パッケージ（G6）

**目的:** 実在の人間（編集・プライバシー担当）が、本文・研究データの権利・公開同意・利益相反・著者表示・ライセンスを確認し、レビュー1件・訂正演習1件・撤回演習1件を実施する。
**注意:** AI が人間のレビュー/同意/COI 確認を行ったと主張してはならない。

## 依頼文（所有者→編集担当）

> 以下の対象物を、あなた自身の判断で確認してください。確認は著者内部だけでなく、必要に応じて別経路の確認を取ってください。結果を「承認した」「承認しない（理由付き）」で記録し、署名または同等の確認手段を添えて返してください。訂正演習と撤回演習は「演習」と明記し、本番撤回にしないでください。

## 確認対象

1. **本文の権利**: paper.pdf / supplements/paper.md の著者性・ライセンス（CC BY 4.0）、引用、第三者素材の有無。
2. **研究データの権利**: data/*.csv, provenance.json, results.json（CC/MIT 区分、LICENSE-NOTICE.txt との整合）。
3. **公開同意**: 誰の同意が必要か（著者本人・データ生成者・コード作者）、同意が取得済みであること。
4. **COI（利益相反）**: 著者/所有者とツール/リポジトリ/TSA/CA 間の利害関係の申告。暗号学的証明ではなく申告と記録。
5. **著者表示・ライセンス**: 「Unjuno」名義・CC BY 4.0/MIT 分離・本人確認の限界の開示文。
6. **プライバシー**: 個人データ/患者原本が含まれないこと、取り出し可能なメタデータの最小化。

## レビュー過程1件（必須）

- 少なくとも1件のレビュー記録を作成する（形式自由: Issue コメント/文書/メール等）。
- 内容: 対象版・対象資産・指摘と回答・最終判断（承認/不承認・理由）。
- 決定は人間の判断で行い、AI は指摘の候補列挙にしか使わない。

## 訂正演習1件（必須）

- 目的: 誤りを見つけ、公開済み版の履歴を壊さずに訂正できることを示す。
- 手順例: 公開済み v1 を「演習」と明記して一部修正した v2 相当の変更を**別リポジトリ（合成）**に DEMO として実施し、Immutable Release を上書きしないことを確認。本紙 paper の v1 を実際に変更/再公開しないこと。
- 記録: 「演習」であること・対象・修正内容・版/履歴が保持されたこと・旧版が引き続き検証可能であること。

## 撤回演習1件（必須）

- 目的: 撤回が発生した場合に、Immutable Release の履歴を破壊せず「撤回済み」と表示・誘導できることを示す（削除しない運用）。
- 手順例: 合成 repo の Release を「RETRACTED（演習）」とマークするメタデータ/README 更新を Issue/PR で実施し、旧 Release は取得可能・検証可能であることを確認。本紙 paper Release には一切の変更を加えないこと。
- 記録: 「演習」であること・対象・表示方法・旧版の検証可能性。

## 記録すべき項目（G6 証拠）

- 確認対象リストと各判定（承認/不承認・理由・日時・確認手段）
- レビュー1件の記録（対象・指摘・回答・判定）
- 訂正演習1件・撤回演習1件の記録（演習と明記、対象、版/履歴保持の確認）
- 編集担当の氏名/識別子と署名（または同等の確認手段）
- 患者原本・秘密鍵が含まれないことの確認

## PASS 条件

- 上記が全て揃うこと。署名のない AI 作成の確認書は無効。演習を本番撤回に見せかけてはならない（演習であると明記）。
