### Reproduced defect / fixed code

`scripts/research_package.py` previously loaded YAML with last-one-wins semantics. Three focused regression tests were observed **failing for the expected reason** before the proposed fix: conflicting `public_confirmed`, duplicated `license`, duplicated nested author name. The new safe loader rejects duplicate mappings, including YAML merges with conflicting keys. Focused local suites after fix: `test_hardening.py` **11/11 PASS**, `test_research_package.py` **14/14 PASS**, `test_release.py` **11/11 PASS**, and `test_citation_validation.py` **9/9 PASS**. GitHub CI **on the new SHA** remains mandatory before closing A01. Local full-suite execution exceeded the available timeout and is **not** a claimed local full-suite PASS.

## External evidence / scientific limits

- GitHub's [immutable release documentation](https://docs.github.com/en/code-security/concepts/supply-chain-security/immutable-releases): tags and assets are locked after publication, but title/notes remain editable; immutable releases include release attestations. Verify actual published assets and attestations, not README assertions.
- [FAIR principles](https://doi.org/10.1038/sdata.2016.18) require persistent discovery, rich metadata, provenance, licensing and reuse. Implementation is partial without discoverable/versioned identifiers and external custody.
- A timestamp may support existence of a digest by the TSA-signed time under independent trust. It **cannot** establish first publication, authorship, scientific validity or genuine human peer review. Signed TSA `accuracy` may be absent; do not invent a numeric time uncertainty.

**Auditor independence:** none; current work is internal engineering audit only. Independent security/privacy review is a mandatory future gate.
